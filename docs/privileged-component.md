# 公共权限组件 1.1.2（API v1，目录布局 v2）

安装后的代码布局：

```text
/data/.minas-privileged/
  minas-helper                 稳定 sudo / cron 入口
  component_admin.py           稳定 root 安装器入口
  common/                      通用运行库、安装事务、用户状态 IO、短期监控缓存
  modules/<插件名>/            各插件独立的提权实现
  modules/sshrecovery/var/      SSH 恢复密钥、记录、设置和临时下载（root 0700）
  registry.json                root 授权、版本与已登记代理端口
  component.lock / docker.lock 保留固定 inode 的跨插件锁
  users/                       原有调度状态（不迁移、不重写）
```

Docker 管理、计划任务、SSH 恢复、Mihomo、控制中心的 `payload/common/` 只含同一份共有代码、自己的模块和摘要清单；底部从实际接口动态显示组件版本。没有提权功能的文件快传、下载中心不携带、不安装公共组件，不依赖组件安装/卸载入口，也没有 sudo 权限。私有实现唯一保存在各自 `payload/common/modules/<插件>/`，直接维护并安装这同一份代码，不保留 `payload/system/`、符号链接或其他私有副本。共有代码的维护源在本目录；`workspace-tools/sync-privileged-component.py` 只同步共有文件、读取既有私有模块并更新摘要，不覆盖或复制私有实现。

共有组件缺失则安装，旧版本则升级，相同或更高版本保持不动；同版本不同字节视为损坏或未升版本，拒绝覆盖。不兼容 API 拒绝升级，不降级共有代码；当前插件模块单独按版本更新，绝不复制或覆盖其他插件模块。安装任一插件也不自动给其他插件授权。

更新在公共锁下等待现有调用完成；异步 Docker 操作、任务刚保留的 worker 会阻止更新。固定入口和 API v1 保持兼容，共有部分升级时尚未迁移的旧模块继续从原位置加载，直到所属插件自行升级。升级不重启服务、不触发下载、不改任务、配置、密钥。安装失败回滚，成功清理临时回退目录；只有显式卸载保留必要的恢复备份。

Mihomo 只能操作 root 登记的代理端口。Docker 代理切换、控制中心重启 Docker 与 Docker 管理、调度共用事务锁。身份取自 sudo，不接受跨用户请求；不提供任意 root 命令接口。控制中心执行普通用户可编辑的控制脚本前必须降为该 NAS 用户。

旧独立助手只有在相关授权和调用入口迁移后才清理。SSH 自启服务和独立应急程序保持原位置，不依赖插件页面可用。

1.1.2：显示缓存与任务输出日志通过降权 IO 存入各插件官方 `tmp/cache/`。原 `/run` 监控与出口探测缓存不再写入 `/run`。缓存不能作为授权或命令执行依据；root 事务锁、调度状态与 SSH 恢复材料仍在受保护目录。普通插件 PID、日志和更新暂存使用 `tmp/runtime/`。组件卸载检查先于插件去登记；最后一个用户引用移除时同步清理模块和分发版本记录。

SSH 数据只在 SSH 恢复插件自身升级时迁移，共有部分升级不会移动其他模块数据。迁移在组件锁与恢复操作锁下原子移动整个旧目录，保留文件内容、权限和锁 inode；新旧数据同时存在则拒绝合并。独立应急程序同步修改路径，运行中的应急操作会阻止迁移。失败回滚到原目录，运行数据不放进参与原厂校验的源码目录。旧离线应急包可读原数据位置，新导出的包兼容新旧路径。
